# Новый проект C++ по спецификации

Аргументы: `/new-cpp-project <Name> <каталог>`.

- `<Name>` — имя проекта в PascalCase (например, `Sandbox`), обязательно.
- `<каталог>` — каталог назначения относительно корня этого репозитория (например, `../sandbox`),
  обязательно. Без него — остановиться и спросить; генерировать внутрь текущего репозитория нельзя.

Единственный источник требований — `SCAFFOLD.md` в корне этого репозитория.

## Порядок действий

1. **Прочитать `SCAFFOLD.md` целиком.**
   Это техническое задание: не отступать от него и не дополнять своими решениями. Если для
   файла или настройки спецификация не даёт однозначного ответа — остановиться и задать вопрос
   разработчику; ответ вносит в `SCAFFOLD.md` разработчик, после чего генерация начинается заново.
   Файлы текущего репозитория (`src/`, `automation/`, `cmake/` и другие) образцом не считать и
   не копировать: скилл обязан давать тот же результат из любого каталога.

2. **Проверить каталог назначения.**
   Каталог не существует или пуст. Если в нём есть файлы — остановиться и запросить решение
   разработчика; ничего не удалять самостоятельно.

3. **Сгенерировать структуру.**
   Создать все файлы из раздела 1 «Структура каталогов» и только их. Подставить `<Name>` во всех
   местах, где спецификация его использует:
   - каталог `src/<Name>/` и `EXCLUDE = src/<Name>/Tests`, `INPUT = src/<Name>` в `Doxyfile`;
   - `project(<Name> LANGUAGES CXX)` в корневом `CMakeLists.txt` и в `src/<Name>/CMakeLists.txt`,
     `VS_STARTUP_PROJECT <Name>`;
   - `HeaderFilterRegex` в `.clang-tidy`;
   - `PROJECT_NAME = "<Name>"` в `automation/common.py`;
   - `PROJECT_NAME` в `Doxyfile`, `site_name` и `site_description` в `mkdocs.yml`;
   - `title` в `config.json`;
   - заголовок `# <Name>`, имена целей и бинарников в `README.md` и `docs/*.md`;
   - пути артефактов `<Name>.exe` и `<Name>` в `.github/workflows/build.yml`.
   `<owner>` и `<repo>` в README оставить заполнителями: репозитория на GitHub ещё нет.
   C++ код после создания отформатировать: `python automation/format_files.py`.

4. **Выполнить самопроверку** из каталога назначения строго в этом порядке (на Linux — `python3`):
   1. `python automation/generate_project_files.py`
   2. `python automation/build_debug.py`
   3. `python automation/run_tests.py`
   4. `python automation/format_files.py --check`
   5. `python automation/run_tidy.py`
   6. `python automation/run_asan.py`
   7. `python automation/build_docs.py`
   8. запуск `build/bin/Debug/<Name>.exe` (Linux — `build/Debug/bin/<Name>`) из корня проекта:
      вывод `Hello, <Name>! Window: 800x600`.
   На первой ошибке остановиться. Если сгенерированный файл расходится со спецификацией —
   привести его к спецификации и повторить проверку с этого этапа. Если ошибка вызвана самой
   спецификацией (требование неполно, противоречиво или неверно) — остановиться и сообщить
   разработчику, какое требование и в каком разделе нужно править.

5. **Инициализировать Git.**
   `git init -b master` в каталоге назначения, `git add` с перечнем созданных файлов по имени
   (не `git add .`), коммит `chore: project scaffold`. Ничего не отправлять в удалённый репозиторий.

6. **Выдать отчёт.**
   - путь к созданному проекту;
   - перечень созданных файлов;
   - статус каждого этапа самопроверки одной строкой (`[OK]` / `[FAIL]`);
   - команда внешней приёмки из корня репозитория курса:
     `python checks/scaffold.py <каталог> --report reports/scaffold-report.txt`.

## Жёсткие правила

- Все имена целей, каталогов и файлов строятся строго от шаблона `<Name>`. Имя `App` и другие имена
  из текущего репозитория в сгенерированном проекте не встречаются, если проект не назван так явно.
- Версии библиотек, инструментов и GitHub Actions берутся исключительно из спецификации.
- Не добавлять файлы и зависимости сверх спецификации: никаких `LICENSE`, `CONTRIBUTING.md`,
  `CMakePresets.json`, дополнительных примеров и альтернативных конфигураций.
- Комментарии в C++, CMake и Python — на английском языке.
- Единственный источник истины — `SCAFFOLD.md`.
- Если проверка не проходит из-за неточности в спецификации, агент обязан остановиться и запросить
  правку. Изменять `SCAFFOLD.md` вправе только человек; агент его не редактирует.
